# 章节测验（work）自动答题

挂机模式下，前台服务会自己巡检课程 → 发现新测验 → 拉题 → 字体反解 → 查题库 → 作答 → 按风控节奏提交 → 回查。
用户只需要打开一次 App（挂机开关默认开），之后不用操作。

## 协议（均已用真实页面验证）

### 取题

```
GET https://mooc1.chaoxing.com/mooc-ans/api/work?api=1
    &workId=<jobid 去掉 work- 前缀>&jobid=work-<id>&originJobId=work-<id>
    &needRedirect=true&skipHeader=true&knowledgeid=<k>&ktoken=<t>
    &cpi=<c>&ut=s&clazzId=<cl>&type=&enc=<e>&mooc2=1&courseid=<cid>
```

- `enc` / `ktoken` / `knowledgeid` / `cpi` 来自 `GET /mooc-ans/knowledge/cards?...`：
  `mArg.attachments` 里 `type == "workid"` 的卡片给 `workid` / `jobid` / `enc`；
  `mArg.defaults.ktoken` 给 ktoken；`mArg.cpi` 给 cpi。
- **必须带 `api=1`**，否则只有外壳页。
- 已交卷时返回 record 页，按「已交卷 / 查看详情 / 得分」判定并跳过。

### 解析

- 题量：`div.ceyan_name` 里的「题量: N」
- 题块：`div.singleQuesId`，id 是 `question<qid>`，**类名全都一样**
- 题型：`input#answertype<qid>` 的 value —— 0 单选 / 1 多选 / 2 填空 / 3 判断 / 4 简答
- 选项：`span.num_option` 的 `data="A|true|false"`，判断题第一段是 `true`/`false`

### 字体反解

- `style#cxSecretStyle` 里 `@font-face{src:url(data:font/ttf;base64,...)}`，是思源黑体改了 glyf 名
- 用密文字体把字画到 64×64 位图 → 降采样 16×16 → 与参考字体渲染的候选字
  （GB2312 一级 3755 常用字 + ASCII + 标点）做余弦相似度最近邻
- **参考字体要一整套**：系统黑体/宋体/等宽/默认 + `/system/fonts` 里名字带
  CJK / NotoSans / NotoSerif / DroidSansFallback 的字体文件 + `assets/fonts/`，
  每套先做「能画中文」体检（`中`/`国` 都要有形状且不相同），逐字取最优并记录来源。
  只放一套时实测整卷相似度只有 0.86，解出来是「吉年夹，中圆兵户党」这种部分字错。
- 阈值按卷自适应（中位数 − 0.08，上限 0.86）；同时统计「最优-次优间距」，
  间距 < 0.02 的字单独计数（`gapTight`），目前只记日志，用来判断要不要再收紧。
- 康熙部首区（U+2F00–U+2FD5）经 NFKC 归一化回 CJK

### 提交（2026-11 用真实账号逐条验证，附证据）

```
POST https://mooc1.chaoxing.com/mooc-ans/work/addStudentWorkNewWeb
     ?_classId=<classId>&courseid=<courseId>&token=<enc_work>
     &totalQuestionNum=<页面里的 32 位 hash>&workid=<数字 workId>
     &cpi=<cpi>&jobid=work-<id>&knowledgeid=<k>&testmooc2=1&originJobId=...
     &ua=pc&formType=post&saveStatus=1&version=1
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest, Origin/Referer: mooc1
```

**接口就是页面 form 的 action 原文**（老版页面是 `/mooc-ans/work/addStudentWorkNewWeb?...`，
注意 `totalQuestionNum` 是页面里那个 32 位 hash，不是题数）。解析不到 action 时退回
`/mooc-ans/work/addStudentWorkNew` —— 实测这条也能成，前提是字段齐全。

**body = 页面 form 里所有 name 非空的控件，一个都不许少**：

| 字段 | 说明 |
|---|---|
| `courseId` `classId` `cpi` `knowledgeid` `jobid` `workRelationId` | 原样带回 |
| `workAnswerId` / `answerId` | 草稿 id，原样带回（`answerId` 单删不致命，但别删） |
| `totalQuestionNum` | 页面里的 32 位 hash |
| `enc` / `enc_work` / `workTimesEnc` / `randomOptions` / `api=1` / `mooc2=1` | 原样 |
| `answerwqbid` | 全部 qid 逗号拼接，**结尾留一个逗号** |
| `answer<qid>` | 选择题答案：单选 `A`、多选 `ABC`（升序拼接）、判断 `true`/`false`；**未答的题保留空值** |
| `answertype<qid>` | 题型，原样带回；未答的题也要在 |
| `answerEditor<qid><空号>` | 填空题答案（实测没有 `answer<qid>`），如 `answerEditor4047582721` |
| `pyFlag` | 暂存 = `1`；正式提交 = 空 |

实测四种写法的结果（同一账号、同一门课）：

| 写法 | 服务端返回 |
|---|---|
| 丢弃所有 `answer*` 字段 + 漏答 1 题（老代码） | `{"msg":"无效的提交，参数异常！","status":false}` ← 真机 bug |
| 完整字段（含未答题目空 `answer<qid>`） | `{"msg":"success!","stuStatus":4,"status":true}`，回查 80 分（漏答题 0 分） |
| 完整字段但缺填空题的 `answertype<qid>` | `{"msg":"无效的参数：code-2！","status":false}` |
| 完整字段、只删 `answerId` | `success`，回查 100 分（不致命） |

结论：**不是令牌/query/`pyFlag` 的问题，是表单字段被过滤掉了**。服务端按 `answerwqbid`
里的 qid 逐个点数，少一个字段就报参数异常。

### 回查

`/mooc-ans/work/record-list` 对章节测验是死的（实测回「此作业已被删除」）。
正确做法：**交卷后再拉一次 `api/work`**，服务端会 302 到
`selectWorkQuestionYiPiYue`，页面里带：

```html
<span class="ans_number">第1次作答<i></i></span>
<span class="achievement">本次成绩<i>80</i>分</span>
```

`RecordParser.parseList` 就解析这两个（`times` / `score`），查不到记录时 `times=0`，
上层据此判「没交上」。

## 答案来源

三种模式，顺序写死在代码里，不会因为配置搞反：

| provider | 行为 |
|---|---|
| `auto` / `yanxi` / `lemon` / `tikuadapter` | 题库优先，没命中再 LLM（LLM 没配 key 就留空） |
| `llm` | 纯大模型，完全不查题库 |
| `off` / `none` / 留空 | 都不查，只暂存/留空 |

题库：

- `auto`（默认）：内置免费源（柠檬 `api.lemtk.xyz`），不用配置也能跑
- `tikuadapter`：`POST {endpoint}/adapter-service/search`，body `{"question","options","type"}`，读 `answer.answerKey` / `answer.answerText`
- `yanxi`：`tk.enncy.cn`；`lemon`：`lemtk.xyz`
- 查不到就交给下一层，都不行留空，**不猜**

## LLM 兜底（DeepSeek 优先）

- OpenAI 兼容：`POST {baseUrl}/chat/completions`，默认 `https://api.deepseek.com` + `deepseek-chat`
- 设置里填 key / baseUrl / model；开关默认关，填了 key 才会真的调用
- prompt 给题型、题干、带字母的选项，要求**只返回 JSON**（`{"answer":"A"}` 这种），`temperature=0`、`max_tokens=48`
- 回包必须过格式校验才采用：单选框内单字母、多选非空子集（排序去重）、判断 true/false、填空非空且不是拒答；不过就留空并记原因
- 网络失败重试 1 次（20s 超时），仍失败就留空，单题失败不影响整卷
- 日志/通知标来源：题库命中 N / LLM 兜底 M / 留空 K

## 配置（章节测验 → 题库/风控）

- provider 默认 `auto`（内置免费源）；填 `llm` 是纯大模型；`off`/留空都不查
- 题库申请/部署入口（设置里点一下跳浏览器）：
  - 言溪 <https://tk.enncy.cn/>，柠檬 <https://lemtk.xyz/>，tikuAdapter <https://github.com/DokiDoki1103/tikuAdapter>
  - 类型填 `yanxi` / `lemon` 时端点会自动填默认域名，只需要粘 token
- 大模型：开关默认关，key 填了才会调用；默认 `https://api.deepseek.com` + `deepseek-chat`，
  key 申请 <https://platform.deepseek.com/>；baseUrl / model 可改成其它 OpenAI 兼容服务
- 「只暂存」默认关（也就是默认正式交卷），想先看效果再打开
- 巡检间隔默认 10 分钟，按课程轮转；节奏参数（单题停留、提交前等待、两卷间隔）都可调

## 挂机策略

- 命中率 ≥ 阈值（默认 80%）→ 直接交
- 低于阈值 → 照交，但日志/通知标「低置信，建议回看」
- 人脸 / 滑块 / 签到码等硬阻塞 → 只标该卷「需人工」，不中断其它卷，合并推一条通知
- 一题都没答上 → 不交白卷
- 风控：单题 8–20s 随机、提交前 30–60s、两卷间隔 ≥90s、同账号并发 1
- 巡检：每 10 分钟一轮（可调），按课程轮转、每轮只处理少量，已处理的卷 6 小时内不重复

## 未做
