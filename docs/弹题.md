# 视频中途弹题（随堂弹题）

## 为什么必须做

学习通播放器会在某个时间点**暂停视频弹一道题**（插入题 / 随堂题）。答不对，视频就不往下播。
不解决这条，`一门课刷到全绿` 就是空话：视频会永远停在弹题那一刻，任务点永远是灰的。

## 现状（诚实说明）

**接口地址还没有真机抓包确认。** 仓库里现有的抓包资料（`实测结论.md`、`章节测验.md`）
只覆盖登录、签到、课程/章节、视频进度上报和章节测验，**没有弹题的请求/响应样本**。

所以这里的实现是「骨架 + 可插拔」：

```
播放循环 ──每 10 秒──▶ PopQuizBridge.poll(job, 当前秒)
                          │
                   有题 ├─▶ 题库/LLM 作答 ─▶ PopQuizBridge.submit ─▶ 继续播
                          │
                   没题 ├─▶ 进度连续 3 轮不动 = 卡在弹题
                          │        └─▶ 记日志 + 标「需要你本人」+ 跳过这个任务点
                          └─▶ 正常继续
```

## 代码位置

| 文件 | 职责 |
|---|---|
| `study/PopQuiz.kt` | 数据模型 + `PopQuizBridge` 接口 + `PopQuizPolicy` 处置策略（纯逻辑，有单测） |
| `study/ConfiguredPopQuizBridge.kt` | HTTP 实现，地址从设置里读模板；含尽力解析的 `parseQuestions` |
| `study/StudyEngine.kt` | 播放循环里每 10 秒轮询，60 秒超时 |

## 真机抓包之后怎么接上（三步）

1. 打开播放页，等弹题出现，抓 **弹出前后的 XHR/fetch**：
   - 取题请求：一般带 `objectId` / `jobid` / 当前播放秒数
   - 提交请求：一般带题号 + 答案，响应里通常有 `success` 或 `isRight`
2. 把两个 URL 填到设置里（`popQuizFetchUrl` / `popQuizSubmitUrl`），占位符：
   `{objectId}` `{jobid}` `{courseId}` `{clazzId}` `{cpi}` `{time}`
3. 如果响应字段和 `ConfiguredPopQuizBridge.parseQuestions` 里猜的（`questions/question/data/list/result`、
   `id/questionId/qid`、`stem/title/question/content`）不一样，改这一个函数即可，
   **不用动播放循环和处置策略**。

设置项目前只能在代码/调试里写（`Settings.popQuizFetchUrl`），没做 UI —— 抓包前做 UI 没意义。

## 兜底行为（没有接口时）

- 不发送任何弹题请求。
- 播放进度连续 3 次轮询（约 30 秒）不前进 → 判定「卡在弹题」：
  - 日志：`[刷课] xxx：播放进度不动了，疑似卡在弹题（没配弹题接口，无法自动作答）`
  - 任务卡片：标为失败，message 带上面这句
  - **不再重试**（`needsHuman` 会直接跳出这个视频），继续下一个任务点
  - 首页「需要你本人」里会体现
- 效果：整门课不会因为一道弹题卡死，但那一个任务点会留在「还差几个任务点」里，
  不会假装全绿。
