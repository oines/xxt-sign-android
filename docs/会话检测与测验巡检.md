# 会话检测与章节测验巡检

两个真机事故的修复记录：**短信验证码账号被判登录失败**，以及**测验数出来却不做**。

## 一、会话检测：不看密码，看真实请求

真机日志：

```
[检测] <账号> 登录失败：该账号是短信验证码登录，请在账号页删除后重新用验证码添加
```

矛盾点：同一个账号 cookie 明明有效（视频一直回填 `isPassed`），但检测路径只看
「有没有密码」，`authType=sms` 的账号没密码 → 直接判失败，整条巡检被拦死。

现在（`CxSession.checkSession` / `probeSession` + `SessionGate`）：

1. **先便宜检查**：账号管理页（`passport2.chaoxing.com/mooc/accountManage`）有 `messageName` → 有效。
2. **再用真实请求探测**：GET `https://mooc2-ans.chaoxing.com/mooc2-ans/visit/interaction`
   - 拿到业务内容（含 `course` / `课程` / `folder`）→ 会话有效
   - 被重定向到 `passport2.chaoxing.com/login`，或页面出现「忘记密码 / 请输入手机号 / fanyalogin」→ 失效
3. **决策表**（`SessionGate.decide`）：

| cookie | 探测 | authType | 动作 |
|---|---|---|---|
| 有 | 有效 | 任意 | 直接用会话（**不碰密码**） |
| 无/失效 | — | `pwd` | 走密码登录 |
| 无/失效 | — | `sms` | 放弃并提示「登录已失效，请在账号页用短信验证码重新登录」 |
| 无/失效 | — | `web` | 放弃并提示「请在账号页打开网页重新登录」 |

容器实测（同一探测页）：

| 会话 | HTTP | 大小 | 登录标记 | 业务特征 |
|---|---|---|---|---|
| 有 cookie | 200 | 103,198 B | 无 | `course`/`课程`/`folder` 全有 |
| 空会话 | 200（跳登录页） | 35,620 B | 有「忘记密码」 | 全无 |

`login()` 里也加了闸门：`authType != pwd` 的账号**一律不拿密码去试**，
提示语改成「用短信验证码重新登录」，不再让人删账号。

## 二、测验巡检：跟课程运行解耦

原来 `maybeStartQuizPatrol()` 要求 `CourseRunQueue.anyActive()`，
课程一暂停，测验巡检也跟着停。

现在只要**这门课被点过开始过**（`CourseRunQueue.states` 里还有它，哪怕是暂停态）就跑测验巡检。
视频可以暂停，测验照常往下做。

一轮的额度也调大了：`maxCourses = 1`（游标轮换课程）、`maxQuizzes = 8`、`maxChaptersPerCourse = 400`，
否则 58 章 59 份要轮好几轮才轮得到。

## 三、数出来就得真的做

- `QuizAutoRunner` 原来对**每一份**都 `QuizHandledStore.mark()`，包括失败/异常的，
  等于一次失败 6 小时不再碰。现在只有 **已提交** 或 **需人工** 才记账，失败的下轮重试。
- `MonitorService.quizPatrol` 现在对每份结果都打一行日志：
  - `[测验] 已交《课程 · 章名》：85 分（答上 5/5）`
  - `[测验] 课程 · 章名 没交上：<原因>`
  - `[测验] 课程 · 章名 需人工：<原因>`
  再加上原有的汇总通知（每份都带分数）。
