# 学习通验证码机制（实测 + 逆向确认）

## 一、总览：两个阶段，两套验证码

| 阶段 | 服务 | captchaId | 验证码类型 | 通关产物 | 产物去向 |
|---|---|---|---|---|---|
| **登录** | `captcha.chaoxing.com` | `GcXX5vewqE7DezKGlyvleKCnkTglvGpL` | 点选（`textclick` 中文 / `iconclick` 英文） | `validate` 字符串 | `fanyalogin` **表单字段** `validate` |
| **签到** | `captcha.chaoxing.com` | `Qt9FIw9o4pwRjOyqM6yizZBh682qN2TU` | **滑块**（背景图 + 抠图两张） | `validate` 字符串 | `stuSignajax` **query 参数** `validate` |

两者共用同一套 SDK（`https://captcha.chaoxing.com/load.min.js`）和同一套 JSONP 接口，
只是 `captchaId` 和 `type` 不同。

> 所以"签到弹滑块、登录弹点选"是正常的，不是同一个东西。

## 二、签到阶段：什么时候会被要求验证码

**可以在签到之前就知道。** 活动详情接口返回三个闸门字段：

```http
GET https://mobilelearn.chaoxing.com/v2/apis/active/getPPTActiveInfo?activeId=<aid>
```

| 字段 | 含义 |
|---|---|
| `ifNeedVCode == 1` | **本次签到要求图形验证码** |
| `openCheckFaceFlag == 1` | 要求人脸识别（需要人脸图片的 `objectId`） |
| `ifopenAddress == 1` | 要求位置（配合 `locationText` / 经纬度） |

另外详情里 `ifphoto == 1` 是拍照签到，`otherId` 决定普通/二维码/手势/位置/签到码。

**签到接口的其它已知门槛：**

- 预签到 `preSign` 返回 **HTTP 403** → 会话失效，需要重新登录
- `stuSignajax` 的状态码 `1 / 2 / 3 / 9` 表示"已签到"类终态

## 三、签到滑块：完整接口流程

### 1. 取配置（拿一个 t）

```http
GET https://captcha.chaoxing.com/captcha/get/conf?callback=cx_captcha_function&captchaId=Qt9FIw9o4pwRjOyqM6yizZBh682qN2TU&_=<ts>
```
JSONP 响应，取出数字字段 `t`。

### 2. 取图片

```http
GET https://captcha.chaoxing.com/captcha/get/verification/image?...
```
返回：

| 字段 | 说明 |
|---|---|
| `captchaId` / `type` / `version` / `token` | 本次验证的标识，校验时要原样带回 |
| `captchaKey` / `iv` | 图片相关密钥/向量，校验时要带回 `iv` |
| `shadeImageUrl` | 背景图（带缺口） |
| `cutoutImageUrl` | 滑块小图（带透明通道） |

> 这两张图就是滑块的原料：**求小图在背景图上的水平偏移量**，就是要拖的距离。
> 不要用"最暗区域"定位，照片暗部会给出错误偏移；要用尺度拟合最小残差。

### 3. 提交偏移量，换 validate

```http
GET https://captcha.chaoxing.com/captcha/check/verification/result?callback=cx_captcha_function
      &captchaId=<captchaId>
      &type=<type>
      &token=<token>
      &textClickArr=[{"x":<偏移量>}]
      &coordinate=[]
      &runEnv=10
      &version=<version>
      &t=a
      &iv=<iv>
      &_=<ts>
Header: Referer: <preSign 页面的 URL>
```

JSONP 响应：

- `error == 1` → `msg` 是失败原因
- `result == true` → `extraData` 里是 `{"validate":"..."}`，**这就是要的东西**
- `result == false` → 没滑对，重来

### 4. 带上 validate 重新签到

```http
GET https://mobilelearn.chaoxing.com/pptSign/stuSignajax?...&validate=<validate>
```

`validate` 与本次活动与会话绑定，**每个账号要各滑一次**。

## 四、登录阶段

- 页面脚本从 `captcha.chaoxing.com/load.min.js` 载入 SDK，
  用 `captchaId=GcXX5vewqE7DezKGlyvleKCnkTglvGpL`、`mode=popup` 初始化。
- 中文环境是 `textclick`（按顺序点文字），英文是 `iconclick`。
- 通过后回调给出 `data.validate`，被写进表单的 `validate` 字段，
  随 `fanyalogin` / `fanyaloginbycode` 一起提交。
- 短信验证码发送接口（`/num/phonecode`）前也会走同一个 `capInstance` 弹窗，
  所以**发验证码也可能被验证码拦住**。

## 五、对实现的启示

1. **先探测、后动作**：一键签到时先看 `ifNeedVCode`，
   提前知道哪些账号会被拦，而不是签失败了才知道。
2. **滑块可以做成 App 内的人工拖动**：把 `shadeImageUrl` 和 `cutoutImageUrl`
   直接画到界面上，人拖着滑块对准缺口，松手时把 x 提交给 check 接口换 `validate`。
   全程不需要 WebView，也不需要真的"破解"。
3. **点选类不做自动解**：登录那套是点选，语义相关，图像处理解不了，
   必要时用带 Cookie 的 WebView 兜底。
4. **人脸识别是另一个门槛**（`openCheckFaceFlag`），需要人脸图片，单列处理。
