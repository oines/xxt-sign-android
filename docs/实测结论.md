# 真实账号实测结论（54 个真实签到活动）

数据来源：某真实账号的历史签到活动（共 54 个），逐个拉
`getPPTActiveInfo` / `signDetail` 统计得到。**这是实测，不是推断。**

## 一、闸门分布

| 闸门组合 | 数量 | 能否自动 |
|---|---|---|
| 无闸门 | 36 (67%) | ✅ 全自动 |
| 人脸 + 位置 | 9 (17%) | ❌ 人脸，放弃 |
| 滑块 | 5 (9%) | ⚠️ 人工滑一下 |
| 位置 | 3 (6%) | ✅（需自备坐标） |
| 滑块 + 位置 | 1 (2%) | ⚠️ 人工滑 + 坐标 |

**能自动签的占 67%，加人工滑块后 78%。**

## 二、按签到类型

| `otherId` | 类型 | 数量 | 闸门情况 |
|---|---|---|---|
| 2 | 二维码 | **36 (67%)** | 21 无闸门 / 9 人脸+位置 / 5 滑块 / 1 滑块+位置 |
| 5 | 签到码 | 7 | 全部无闸门 |
| 0 | 普通 / 拍照 | 6 | 全部无闸门 |
| 4 | 位置 | 3 | 全部要位置 |
| 3 | 手势 | 2 | 全部无闸门 |

**二维码签到是绝对主力（67%）。**

## 三、字段可得性（关键）

| 字段 | 实测结果 | 影响 |
|---|---|---|
| `locationLatitude` / `locationLongitude` | **54/54 全为空** | 教师坐标拿不到！位置签到只能靠手机定位或手动设置 |
| `locationText` | 有值，如「XX 市 XX 区 XX 学院」 | 只能当提示语 |
| `signCode` | 33/54 非空 | 二维码签到会返回它 |
| `enc` | 54/54 空 | 都是已结束活动，`enc` 只在进行中有效，无法从此判断 |
| `ifNeedVCode` | 54/54 全为 0 | 滑块**不是常规流程**，是风控临时触发 |

## 四、类型 / 命名的不一致（写代码要小心）

| 位置 | `otherId` 类型 |
|---|---|
| `activeList[].otherId` | **字符串** `"2"` |
| `signDetail.otherId` | **整数** `2` |
| `getPPTActiveInfo.otherId` | **整数** `2` |

Android 的 `JSONObject.optInt` 能解析字符串，所以 `optInt` 两种都吃。
但**别用 `==` 直接比**，会踩坑。

另外 `activeList[].nameOne` 并不总是类型名：
- 普通签到 → `"普通签到"`
- 位置签到 → `"20260920"`（日期）
- 二维码签到 → `"专业技能大赛备赛 ... 签到20261013"`

**所以判断类型必须用 `otherId`，不能用 `nameOne` 去猜。**

## 五、其它闸门字段

`getPPTActiveInfo` 里还有这些（本项目暂未处理）：

```
openPreventCheatFlag   防作弊
openSignOutFlag        签退
openCheckWeChatFlag    微信校验
openCheckFaceFlag      人脸识别
```

## 六、由此确定的实现策略

1. **位置签到**：教师坐标拿不到 → 必须有本机定位或手动坐标，
   否则**明确报错**，不要送 `-1,-1` 去浪费机会（已按此改）
2. **手势 / 签到码**：`signCode` 可能为空 → 自动取 + 手动输入兜底
3. **二维码签到**：动态 `enc` 从 `signDetail` 现取，`ifRefreshEwm=1` 时预签到带 `rcode`
4. **人脸识别**：直接跳过，给出明确文案（已实现）
5. **滑块**：`ifNeedVCode=1` 才触发，属少数（6/54）→ 人工滑
6. **课程解析**：必须走 `backclazzdata` 的
   `channelList[i].content.id`(clazzId) + `content.course.data[0].id`(courseId)，
   通用遍历器匹配不到（已修）
